## 1. Toolchain & Environment Verification Log

Before modifying any file, the repository and build environment were inspected:

* **Sandbox VM Toolchain Check**:
  * `node -v`: `v18.20.4` (Available — used for JavaScript syntax & AST validation).
  * `python3`: `3.11` with `sqlite3 3.40.1` (Available — used for deterministic SQL migration, constraint, and seed verification).
  * `gcc`: `12.2.0` (Available).
  * `go`: The isolated container VM does not have the `go` binary installed in `/usr/bin` or `/usr/local/go/bin` and has no outbound network access. In accordance with Non-Negotiable Rule #13 ("Do not invent test results"), `go test`, `go vet`, and `go build` cannot be executed inside this VM container directly; instead, Go source syntax, package imports, and type contracts are verified deterministically via static structural checks, while SQLite migrations/seeds and JavaScript/Frontend logic are executed and verified directly via `sqlite3` and `node --check`.

### P1 — Core Architecture, Offline Diagnostics, Persistence & Security

| ID | Problem | Severity | Affected Files | Why It Is a Problem | Recommended Solution | Dependencies |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **P1-01** | **Misleading "AI Mentor" uses hardcoded `strings.Contains` heuristics while claiming to be an AI** | **P1** | `internal/mentor/mentor.go`, `web/index.html` | Calling `strings.Contains(code, "panic(")` an "AI Mentor" misleads learners into thinking static substring matching is artificial intelligence, and worse, outputs `"No critical concurrency, SQL injection, or resource-leak anti-patterns detected"` when no substring matches—creating false security confidence. | Remove `internal/mentor` and replace it with an offline **Go Code Review & Diagnostics Lab** (`internal/modules/diagnostics`). Use transparent rule IDs (`GO-SEC-001`, `GO-CONC-002`, `GO-DB-001`, `GO-ERR-001`, plus `gofmt`/`go vet`/`staticcheck` integration), classify findings honestly (`confirmed_diagnostic`, `potential_issue`, `educational_heuristic`, `no_finding_detected`), and explicitly explain static analysis limitations. Add optional `AI_PROVIDER=none` interface stub for future local Ollama use. | P0-03. |
| **P1-02** | **Frontend does not communicate with the Go backend API and lives in a single monolithic HTML file** | **P1** | `web/index.html` | The frontend is a single 314KB file with no modular component separation (`frontend/src/`) and does not call backend REST endpoints when running against the Go server. | Create a clean modular frontend structure under `frontend/src/` (Svelte + TypeScript + Vite components, stores, services, and types) AND compile/bundle a self-contained build to `web/index.html` (and Canvas preview) that uses an API service layer (`fetch('/api/v1/...')`) with automatic offline in-memory/localStorage fallback when previewed standalone in Canvas. | P0-02, P0-03. |
| **P1-03** | **Docker Compose & Makefile unsafe defaults (`docker compose down -v`, public DB ports, hardcoded credentials, unwanted Redis startup)** | **P1** | `docker-compose.yml`, `Makefile` | 1) `Makefile` runs `docker compose down -v` in `docker-down`, which **destroys persistent PostgreSQL volumes** on normal stop! 2) `docker-compose.yml` binds PostgreSQL (`5432:5432`) and Redis (`6379:6379`) to `0.0.0.0` publicly by default. 3) Redis starts unconditionally even though no backend feature uses it. 4) `Dockerfile` has no `HEALTHCHECK`. | 1) Change `make docker-down` to `docker compose down` (preserving volumes) and move volume deletion to `make docker-clean-volumes` with an explicit warning. 2) Bind DB ports to `127.0.0.1:${POSTGRES_PORT:-5432}:5432`. 3) Put Redis behind `profiles: ["cache"]`. 4) Use `${POSTGRES_PASSWORD:?error}` env interpolation and add container `HEALTHCHECK`. | P0-01. |
| **P1-04** | **Missing CORS allowlist, Rate Limiting, and centralized error envelope in HTTP layer** | **P1** | `internal/api/server.go`, `internal/config/config.go` | `config.go` parses `RATE_LIMIT_RPS`, and `.env.example` defines `CORS_ALLOWED_ORIGINS`, but `server.go` implements neither CORS middleware nor token-bucket rate limiting. | Implement `internal/platform/http/middleware.go` with Request ID, structured `slog` logging, panic recovery, CORS allowlist enforcement, IP token-bucket rate limiting, and centralized RFC 9457-style error responses. | P0-02. |
| **P1-05** | **Database schema lacks normalized tables for Modules, Lesson Sections, Exercises, Quizzes, Case Study Steps, DB Scenarios, and Diagnostic Rules** | **P1** | `migrations/001_initial_schema.sql` | Storing everything in a single `lessons` table with 6 giant JSON text blobs prevents relational querying of modules, exercises, quiz attempts, diagnostic rules, and case study steps. | Upgrade the relational schema to normalize `users`, `curriculum_levels`, `modules`, `lessons`, `lesson_sections`, `lesson_references`, `exercises`, `exercise_test_cases`, `exercise_attempts`, `quizzes`, `quiz_questions`, `quiz_attempts`, `user_progress`, `user_bookmarks`, `user_notes`, `case_studies`, `case_study_steps`, `database_scenarios`, `diagnostic_rules`, and `diagnostic_results` with proper foreign keys, indexes, and rollback (`down.sql`) migrations. | P0-01. |
