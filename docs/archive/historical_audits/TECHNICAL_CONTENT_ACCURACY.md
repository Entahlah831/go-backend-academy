# Go Backend Academy — Deep Technical Content Accuracy Audit

Every technical claim, code example, and reference across the 36 lessons, 14 case studies, and 10 database scenarios was audited against the Go Language Specification, Go 1.22–1.26 release notes, PostgreSQL 17/18 documentation, SQLite WAL documentation, and OWASP API Security Top 10 (2023).

---

## 1. Classification of Technical Content Findings

| ID | Lesson / Component | Technical Claim / Code Snippet | Classification | Technical Audit Details & Required Correction |
| :--- | :--- | :--- | :--- | :--- |
| `TECH-01` | Header Badge & References (`web/index.html` line 23 & 129) | Header badge says `Go 1.23+` and sidebar link says `PostgreSQL 18`, while `go.mod` / `Dockerfile` use `go 1.26.0` and `docker-compose.yml` uses `postgres:17-alpine`. | **Inconsistent Version Labeling** | Align version badges across UI and docs: state `Go 1.22–1.26+` for curriculum compatibility and `PostgreSQL 17+` to match `docker-compose.yml`. |
| `TECH-02` | Lesson `0.1` (`l0-backend-http-lifecycle`) | Uses `http.MaxBytesReader(w, r.Body, 64<<10)` + `dec.DisallowUnknownFields()` + explicit `ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout`, `IdleTimeout`. | **Correct, Production-Grade, Too Early for Absolute Beginners** | Technically 100% accurate and best-practice, but uses pointers, struct tags, and `defer` before Level 1 teaches them. Keep in Level 0 for intermediate learners, but mark `1.0A–1.0F` as recommended prerequisites before attempting the `0.1` code exercise. |
| `TECH-03` | Lesson `1.1` (`l1-memory-slices-maps-escape`) | Explains 24-byte slice header (`ptr`, `len`, `cap`), `runtime.hmap` 8-cell buckets, and `ClonePrefix` using `make([]int, n)` + `copy(out, src[:n])`. | **Correct (With Go 1.24+ SwissTable Caveat Needed)** | Note that starting in Go 1.24+, the Go runtime transitioned the built-in `map` implementation toward SwissTable-based hash tables (`internal/runtime/maps`), while keeping the exact same language spec semantics (non-addressable values, randomized iteration order, fatal concurrent read/write). Adding a 1-sentence note on Go 1.24+ SwissTable internals makes `1.1` even more up-to-date. |
| `TECH-04` | Lesson `2.1` (`l2-gmp-channels-context-workers`) | Explains GMP scheduler (`G`, `M`, `P`, `GOMAXPROCS`, work-stealing runqueues, ~10ms asynchronous preemption via `SIGURG`) and bounded worker pool. | **Correct, But Overloaded in Single Lesson** | All runtime mechanics are accurate (Go 1.14+ `SIGURG` non-cooperative preemption and Go memory model happens-before guarantees). Needs a preceding `2.0` lesson for basic goroutine/channel syntax. |
| `TECH-05` | Lesson `2.2` (`l2-profiling-pprof-benchmarks`) | Recommends setting `GOMEMLIMIT` to ~85% of container cgroup memory limit and capping `sync.Pool` buffer capacity (`bufCap <= maxPooledCap`). | **Correct (Note Go 1.19+ `GOMEMLIMIT` & Container Awareness)** | Accurate best practice (prevents famous `fmt`/`bytes.Buffer` oversized pool retention bug CVE/issue patterns and OOM-kills). |
| `TECH-06` | Lesson `4.1` (`l4-acid-isolation-mvcc`) | Contrasts PostgreSQL `REPEATABLE READ` (Snapshot Isolation using `xmin`/`xmax` with first-updater-wins serialization error `40001`, preventing Lost Updates) vs MySQL InnoDB. | **Correct & Exceptionally High Quality** | One of the strongest database explanations in any Go course; accurately distinguishes SQL-92 theoretical anomalies from PostgreSQL's actual Snapshot Isolation implementation. |
| `TECH-07` | Lesson `5.0` (`l5-stage-e-database-sql-crud-basics`) | Uses `$1` parameter placeholder in `db.QueryRowContext(ctx, "SELECT id FROM users WHERE email = $1", email)`. | **Correct (Clarify Driver Placeholder Syntax)** | Mention explicitly in the Beginner tab that `$1, $2` is PostgreSQL (`pgx`/`lib/pq`) syntax, whereas MySQL and default SQLite drivers use `?` (and that Go Backend Academy's own DB layer automatically rewrites `$1` -> `?` when running on SQLite). |
| `TECH-08` | Lesson `6.1` (`l6-security-auth-owasp`) | Uses `netip.ParseAddr(ip)`, `addr.Unmap()`, and checks `IsLoopback()`, `IsPrivate()`, `IsLinkLocalUnicast()`, `IsLinkLocalMulticast()`, `IsMulticast()`, `IsUnspecified()` to block SSRF. | **Correct (Add DNS Rebinding / `DialContext` Caveat)** | The `Advanced` tab rightly mentions `net.Dialer.Control`, and the `Beginner` tab should remind learners that validating a raw IP string is step 1, while validating the resolved IP inside `http.Transport.DialContext` prevents DNS rebinding TOCTOU attacks. |
